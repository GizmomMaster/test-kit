# Spec Delta

## Purpose

Определяет, как на стадии приёмки объём ручной проверки каждого кейса TestRail зависит от его фактического покрытия автотестами, и как результаты из CI попадают в TestRail и отчёт.

## ADDED Requirements

### Requirement: Объём ручной приёмки по статусу покрытия
Агент `qa` в режиме «приёмка» SHALL определять объём ручного прогона каждого кейса по фактическому статусу в матрице покрытия среза.

#### Scenario: Кейс ПОЛНОСТЬЮ
- **WHEN** фактический статус кейса — ПОЛНОСТЬЮ
- **THEN** qa выполняет на стенде один позитивный шаг кейса как смоук, результаты остальных шагов берёт из CI

#### Scenario: Кейс ЧАСТИЧНО
- **WHEN** фактический статус кейса — ЧАСТИЧНО
- **THEN** qa вручную выполняет шаги со статусами «покрыт логически» и «не покрыт», а для шагов со статусом «покрыт» берёт результат из CI

#### Scenario: Кейс НЕТ
- **WHEN** фактический статус кейса — НЕТ
- **THEN** qa выполняет все шаги кейса вручную

### Requirement: Источник результатов CI для агента
Результаты автотестов агент `qa` SHALL брать из `coverage-report.json` pipeline, который ему передал пользователь. Если отчёта нет, результаты подтверждает пользователь по pipeline, и в отчёте приёмки это помечается.

#### Scenario: Отчёт передан
- **WHEN** пользователь передал qa файл coverage-report.json
- **THEN** qa берёт результаты автотестов по кейсам из него и указывает в отчёте SHA и номер pipeline

#### Scenario: Отчёта нет
- **WHEN** coverage-report.json недоступен (джоба ещё не внедрена или не отработала)
- **THEN** qa запрашивает у пользователя статус тестов кейсов по pipeline и помечает в отчёте «результаты CI подтверждены пользователем»

### Requirement: Красный CI отменяет облегчённую приёмку
Если хотя бы один автотест с меткой кейса упал в CI, `qa` SHALL NOT использовать результат CI для шагов этого кейса.

#### Scenario: Упал помеченный тест
- **WHEN** в CI упал тест с меткой C12345
- **THEN** qa выполняет все шаги C12345 вручную и фиксирует падение автотеста в отчёте

### Requirement: Приёмка без матрицы
Если для среза нет матрицы покрытия, `qa` SHALL выполнять приёмку в прежнем объёме: все шаги вручную.

#### Scenario: Срез по старому процессу
- **WHEN** в test-cases.md среза нет раздела матрицы покрытия
- **THEN** qa проводит полный ручной прогон и отмечает в отчёте, что покрытие автотестами не учитывалось

### Requirement: Источник результата в отчёте и TestRail
В `test-report.md` и в результатах TestRail для каждого шага SHALL указываться источник результата: ручной прогон на стенде или автотест CI с его именем.

#### Scenario: Шаг закрыт автотестом
- **WHEN** результат шага взят из CI
- **THEN** в отчёте и в `actual` результата шага в TestRail указано «автотест CI» и имя теста

#### Scenario: Внесение результатов в TestRail
- **WHEN** пользователь согласился внести результаты в TestRail
- **THEN** результаты по шагам, взятые из CI, и результаты ручного прогона вносятся одной записью на кейс с результатом по каждому шагу

### Requirement: Запись покрытия в поля кейса TestRail
После приёмки агент `qa` SHALL записать фактическое покрытие каждого кейса среза в поля покрытия TestRail: статус в `Dev coverage`, шаги, автотесты и строку «сверено: <KEY>, <дата>» в `Dev autotests`. Запись выполняется только после явного согласия пользователя.

#### Scenario: Поля есть, пользователь согласен
- **WHEN** приёмка завершена, поля покрытия есть в проекте, и пользователь согласился на запись
- **THEN** qa записывает поля по фактической матрице и перечитывает кейс для сверки

#### Scenario: Полей нет в проекте
- **WHEN** поля покрытия отсутствуют в проекте TestRail
- **THEN** qa пропускает запись полей, не блокирует приёмку и отмечает в отчёте «поля покрытия в TestRail отсутствуют»

#### Scenario: Запись намерения запрещена
- **WHEN** для кейса есть только намерение покрытия со стадии 1, а фактической матрицы нет
- **THEN** qa не записывает поля покрытия
