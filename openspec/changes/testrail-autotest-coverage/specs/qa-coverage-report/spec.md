# Spec Delta

## Purpose

Человекочитаемый отчёт для QA, формируемый в CI: по каждому кейсу TestRail задачи показывает покрытие автотестами, результат этих автотестов в pipeline и объём ручной проверки на приёмке.

## ADDED Requirements

### Requirement: Отчёт формируется в pipeline
Pipeline сервиса SHALL после прогона unit- и интеграционных тестов формировать отчёт покрытия в двух видах: `coverage-report.html` для людей и `coverage-report.json` для агентов. Оба файла сохраняются артефактами pipeline.

#### Scenario: Pipeline с матрицей
- **WHEN** pipeline выполнен для ветки, в которой есть матрица покрытия среза
- **THEN** среди артефактов pipeline есть `coverage-report.html` и `coverage-report.json`

#### Scenario: Матрицы нет
- **WHEN** в ветке нет матрицы покрытия
- **THEN** отчёт не формируется, и pipeline из-за этого не падает

### Requirement: Отчёт сформирован по кейсам
Отчёт SHALL быть сгруппирован по кейсам TestRail задачи, а не по тестам. Для каждого кейса показываются C-id со ссылкой на кейс, название, статус покрытия, шаги по статусам, автотесты и их результат.

#### Scenario: Кейс с покрытием
- **WHEN** в матрице есть кейс со статусом ЧАСТИЧНО
- **THEN** в отчёте у кейса видны номера шагов «покрыт» и «покрыт логически», тесты каждого шага и их результат в pipeline

### Requirement: Указание объёма ручной проверки
Для каждого кейса отчёт SHALL указывать, что должен сделать QA: смоук одного позитивного шага (ПОЛНОСТЬЮ), ручной прогон перечисленных шагов (ЧАСТИЧНО) или полный ручной прогон (НЕТ). В начале отчёта есть сводка по количеству кейсов каждого вида.

#### Scenario: Сводка отчёта
- **WHEN** QA открывает отчёт
- **THEN** вверху видны число кейсов по статусам, число кейсов с красными тестами и итог «что делать QA»

### Requirement: Красный тест отменяет облегчённую приёмку кейса
Если хотя бы один автотест кейса в pipeline упал, был пропущен или отсутствует в результатах, отчёт SHALL пометить кейс как требующий полного ручного прогона. Для `[Theory]` учитываются все записи.

#### Scenario: Упал один из тестов
- **WHEN** один из тестов кейса ПОЛНОСТЬЮ упал
- **THEN** кейс помечен как проблемный, и для него указан полный ручной прогон

#### Scenario: Тест из матрицы не найден в результатах
- **WHEN** тест, указанный в матрице, отсутствует в результатах pipeline
- **THEN** кейс помечен как требующий полного прогона с пометкой «тест не найден»

### Requirement: Понижения покрытия видны в отчёте
Отчёт SHALL показывать кейсы, у которых фактическое покрытие ниже намерения со стадии 1, вместе с причиной.

#### Scenario: Понижение
- **WHEN** в матрице у кейса есть пометка о понижении
- **THEN** в отчёте у кейса видны план, факт и причина

### Requirement: Расхождение матрицы и трейтов
Отчёт SHALL предупреждать о расхождении между матрицей и трейтами `TestRail` в коде тестов. Сверяются только кейсы текущей матрицы: трейты на кейсы других задач предупреждений не дают.

#### Scenario: Тест в матрице без трейта
- **WHEN** тест указан в матрице для кейса C12345, но не несёт трейта `C12345`
- **THEN** отчёт содержит предупреждение с именем теста и кейса

#### Scenario: Трейт без записи в матрице
- **WHEN** кейс C12345 есть в текущей матрице, тест несёт трейт `C12345`, но в матрице для этого кейса не указан
- **THEN** отчёт содержит предупреждение с именем теста и кейса

#### Scenario: Трейт на кейс другой задачи
- **WHEN** тест несёт трейт `C99999`, а кейса C99999 нет в текущей матрице
- **THEN** отчёт не выдаёт предупреждения по этому трейту

### Requirement: Привязка отчёта к сборке
Отчёт SHALL указывать SHA коммита, номер pipeline со ссылкой, дату формирования и ключ задачи.

#### Scenario: Заголовок отчёта
- **WHEN** QA открывает отчёт
- **THEN** в заголовке видны ключ задачи, SHA, номер pipeline и дата

### Requirement: TestRail только читается
При формировании отчёта pipeline SHALL только читать данные из TestRail (названия кейсов). Pipeline SHALL NOT записывать в TestRail результаты, поля или прогоны. Если TestRail недоступен, отчёт формируется без названий кейсов.

#### Scenario: TestRail недоступен
- **WHEN** при формировании отчёта TestRail не отвечает
- **THEN** отчёт сформирован с C-id без названий и с пометкой «названия кейсов недоступны»

### Requirement: JSON-отчёт содержит те же данные
`coverage-report.json` SHALL содержать те же данные по кейсам, что и HTML-отчёт: статус покрытия, шаги, тесты и их результат, пометки, SHA, pipeline. По нему агент `qa` получает результаты CI.

#### Scenario: Агент читает JSON
- **WHEN** агенту qa передан `coverage-report.json`
- **THEN** агент получает из него результат каждого автотеста кейса без доступа к GitLab
