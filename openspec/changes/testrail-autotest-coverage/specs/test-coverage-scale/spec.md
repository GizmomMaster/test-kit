# Spec Delta

## Purpose

Единая шкала, по которой агенты и люди оценивают, насколько кейс TestRail закрыт unit- и интеграционными тестами: статусы шагов, вывод статуса кейса и формат матрицы покрытия.

## ADDED Requirements

### Requirement: Покрытие оценивается по шагам кейса
Покрытие кейса TestRail SHALL оцениваться отдельно по каждому шагу кейса. Каждому шагу присваивается ровно один статус: «покрыт», «покрыт логически» или «не покрыт».

#### Scenario: Шаг с полной проверкой через тот же интерфейс
- **WHEN** автотест выполняет то же действие через тот же интерфейс, что и шаг кейса, и проверяет все ожидания шага
- **THEN** шаг получает статус «покрыт»

#### Scenario: Шаг, правило которого проверено ниже интерфейса
- **WHEN** автотест проверяет правило, на котором основано ожидание шага, но не через интерфейс кейса
- **THEN** шаг получает статус «покрыт логически»

#### Scenario: Шаг без автотеста
- **WHEN** ни один автотест не проверяет ожидания шага
- **THEN** шаг получает статус «не покрыт»

### Requirement: Статус кейса выводится из статусов шагов
Статус кейса SHALL выводиться из статусов его шагов: ПОЛНОСТЬЮ, ЧАСТИЧНО или НЕТ.

#### Scenario: Все шаги покрыты
- **WHEN** все шаги кейса имеют статус «покрыт» и ни один шаг не зависит от стенда
- **THEN** кейс получает статус ПОЛНОСТЬЮ

#### Scenario: Покрыта часть шагов
- **WHEN** хотя бы один шаг имеет статус «покрыт» или «покрыт логически», но условие ПОЛНОСТЬЮ не выполнено
- **THEN** кейс получает статус ЧАСТИЧНО с перечнем номеров шагов по каждому статусу

#### Scenario: Ни один шаг не покрыт
- **WHEN** все шаги кейса имеют статус «не покрыт»
- **THEN** кейс получает статус НЕТ

### Requirement: Уровень автотеста ограничивает статус шага API-кейса
Для шага, проверяющего HTTP API, статус «покрыт» SHALL давать только интеграционный тест, выполняющий запрос через HTTP. Unit-тест и интеграционный тест ниже HTTP дают максимум «покрыт логически».

#### Scenario: Unit-тест валидатора для API-шага
- **WHEN** ожидание API-шага (код 400 на невалидный ИНН) проверено только unit-тестом валидатора
- **THEN** шаг получает статус «покрыт логически», а не «покрыт»

#### Scenario: Интеграционный тест через HTTP
- **WHEN** интеграционный тест отправляет тот же HTTP-запрос и проверяет код ответа и ключевые поля шага
- **THEN** шаг получает статус «покрыт»

### Requirement: Зависимость от стенда исключает покрытие шага
Шаг, ожидание которого зависит от стенда, SHALL получать статус «не покрыт» независимо от наличия автотестов. Зависимостью от стенда считаются: реальные внешние системы, реальная авторизация, конфигурация стенда, фоновые процессы, UI, интеграции через брокер со смежной системой.

#### Scenario: Шаг с вызовом внешней системы
- **WHEN** ожидание шага зависит от ответа внешней системы, замоканной в автотесте
- **THEN** шаг получает статус «не покрыт», в матрице указывается причина «зависимость от стенда» с названием зависимости

### Requirement: Кейс не про API получает максимум ЧАСТИЧНО
Кейс, шаги которого проверяются не через HTTP API, SHALL получать статус не выше ЧАСТИЧНО, пока для такого вида кейсов не определено понятие «тот же интерфейс».

#### Scenario: Кейс про фоновый обработчик
- **WHEN** кейс проверяет результат фонового обработчика, и все его шаги проверены автотестами
- **THEN** кейс получает статус ЧАСТИЧНО

### Requirement: Матрица покрытия
Покрытие SHALL фиксироваться в матрице. В каждой строке: идентификатор кейса, связанные AC, статус кейса, номера шагов со статусом «покрыт», номера шагов со статусом «покрыт логически», автотесты, а для статуса НЕТ ещё и причина.

#### Scenario: Записи матрицы по кейсам
- **WHEN** агент записывает покрытие кейса
- **THEN** у записи заполнены идентификатор кейса, AC, статус, шаги по статусам и автотесты

#### Scenario: Строка кейса НЕТ из-за стенда
- **WHEN** кейс получил статус НЕТ из-за зависимости от стенда
- **THEN** строка матрицы содержит причину с названием зависимости, а не пустое значение

### Requirement: Неоценённое покрытие не равно НЕТ
Если покрытие кейса не оценивалось (у кейса нет записи в матрице, нет трейтов в коде, поле `Dev coverage` пустое или `Не оценено`), кейс SHALL считаться «не оценено», а не НЕТ.

#### Scenario: Старый кейс без связей
- **WHEN** у кейса пустое поле `Dev coverage` и в коде нет тестов с его трейтом
- **THEN** агенты и отчёт показывают статус «не оценено», а не НЕТ

### Requirement: Матрица — машиночитаемый YAML-блок
Матрица покрытия SHALL храниться в `docs/tests/<KEY>/test-cases.md` как один YAML-блок с фиксированной схемой. Все агенты, которые её пишут или читают, работают по этой схеме. Блок должен разбираться YAML-парсером без ошибок.

#### Scenario: Запись матрицы агентом
- **WHEN** tester или qa обновляет матрицу
- **THEN** результат — валидный YAML по схеме матрицы, без свободного текста внутри блока

#### Scenario: Матрица не разбирается
- **WHEN** YAML-блок матрицы невалиден
- **THEN** отчёт покрытия в pipeline сообщает об ошибке разбора матрицы, а не строится по частичным данным
