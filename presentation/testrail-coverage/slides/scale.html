ШКАЛА ПОКРЫТИЯ

Оцениваем каждый шаг кейса, а не кейс целиком

покрыт

Тест выполняет то же действие через тот же интерфейс и проверяет все ожидания шага. Для API — только интеграционный тест через HTTP

покрыт логически

Правило проверено ниже интерфейса, например unit-тестом валидатора. Шаг всё равно проверяется вручную

не покрыт

Теста нет — или шаг зависит от стенда: внешние системы, реальная авторизация, конфиг, фоновые процессы, UI

ПОЛНОСТЬЮ — все шаги «покрыт»

ЧАСТИЧНО — хоть один шаг покрыт

НЕТ — ничего не покрыто

не оценено ≠ НЕТ

Чтобы QA мог доверять пометке, нужна общая шкала. Оцениваем по шагам кейса. «Покрыт» — тест делает то же самое тем же способом, для API это только интеграционный тест через HTTP. «Покрыт логически» — правило проверено, например unit-тестом валидатора, но то, что endpoint его применяет, не доказано, поэтому такой шаг QA всё равно проверяет. «Не покрыт» — теста нет или шаг зависит от стенда, который тестовый хост не воспроизводит. Из шагов выводится статус кейса. И важно: «не оценено» — это не «нет». У старых кейсов покрытие просто никто не смотрел.
